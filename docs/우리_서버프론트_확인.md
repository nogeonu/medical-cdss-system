# 우리 서버/프론트 정상 확인 (고해상도 뷰어)

워커팀이 정상이면, **우리(서버/프론트)** 쪽이 정상인지 아래 순서로 확인하면 됩니다.

---

## 1. 우리 쪽 구현 요약

| 구분 | 내용 |
|------|------|
| **프록시 경로** | `GET /api/mri/pathology/dzi-proxy/<URL인코딩된_워커_DZI_URL>` |
| **라우트** | `eventeye/urls.py` → `path('api/mri/', include('mri_viewer.urls'))` → `mri_viewer/urls.py` 에 `pathology/dzi-proxy/`, `pathology/dzi-proxy/<path:encoded_path>` |
| **헤더** | Django → ngrok 요청 시 `ngrok-skip-browser-warning: true` 포함 (`_pathology_dzi_proxy_fetch`) |
| **프론트** | `PathologyHighResViewer.tsx` — `DZI_PROXY_PATH = '/api/mri/pathology/dzi-proxy/'`, 외부 DZI URL을 `origin + DZI_PROXY_PATH + encodeURIComponent(url)` 로 변환 → **DZI 메타 + 타일 전부 프록시 경유** |

---

## 2. 우리가 확인할 것

### (1) DZI 프록시 허용 호스트

- 워커 ngrok이 **`*.ngrok-free.dev`** 이면, 허용 목록에 **`ngrok-free.dev`** 가 있어야 함.
- **기본값**: `PATHOLOGY_DZI_PROXY_ALLOWED_HOSTS` 에 `ngrok-free.app`, **`ngrok-free.dev`**, `ngrok.io`, `ngrok.app` 포함 (코드 반영됨).
- 배포 서버에서 환경 변수로 덮어썼다면 `ngrok-free.dev` 가 빠져 있지 않은지 확인.

### (2) 프록시 경로가 배포에 포함되는지

- 배포 시 `mri_viewer.urls` 가 `api/mri/` 아래에 포함되어 있어야 함.
- 실제 요청: `http://34.42.223.43/api/mri/pathology/dzi-proxy/https%3A%2F%2F...` 가 200으로 응답하는지 (브라우저 또는 curl로 확인).

### (3) 브라우저 Network 탭

- 고해상도 뷰어 열었을 때:
  - 요청이 **전부** `.../dzi-proxy/...` 로 가는지 (ngrok 주소로 직접 가는 요청이 없어야 함).
  - 실패한 요청(빨간색)이 있으면 URL·상태 코드 확인 (403 → 허용 호스트, 502 → 워커 연결 등).

---

## 3. 수정한 부분 (ngrok-free.dev)

- **원인**: 워커 ngrok이 `https://xxx.ngrok-free.dev` 인데, 기본 허용 호스트에 `ngrok-free.dev` 가 없어 **403 Forbidden** 이 났을 수 있음.
- **조치**: `PATHOLOGY_DZI_PROXY_ALLOWED_HOSTS` 기본값에 **`ngrok-free.dev`** 추가함.
- 배포 후 한 번 더 고해상도 뷰어로 확인하면 됩니다.
