# 고해상도 뷰어 안 나올 때 로그 확인

"이미지 로딩 중…"만 뜨거나 검정 화면이면, 아래 순서로 로그를 확인하세요.

---

## 1. 브라우저 콘솔 (F12 → Console)

고해상도 뷰어를 연 뒤 다음 로그가 나오는지 봅니다.

| 로그 | 의미 |
|------|------|
| `[고해상도 뷰어] raw dziUrl: https://...` | DB/API에서 받은 워커 DZI URL |
| `[고해상도 뷰어] effectiveDziUrl (프록시): http://34.42.223.43/api/mri/pathology/dzi-proxy/...` | 실제로 OpenSeadragon에 넘기는 프록시 URL |
| `[고해상도 뷰어] open — DZI 로드 성공` | DZI 메타 + 타일 로드 성공 → 로딩 끝나야 함 |
| `[고해상도 뷰어] open-failed — ...` | DZI/타일 로드 실패 (Network 탭에서 실패한 요청 확인) |
| `[고해상도 뷰어] 15초 타임아웃 — ...` | 15초 안에 open/open-failed가 안 옴 → 프록시 403/502 또는 요청 자체 실패 가능 |

- **raw dziUrl**이 비어 있으면 → 해당 주문에 `dzi_url`이 없음 (워커가 보내줘야 함).
- **effectiveDziUrl**이 `http://34.42.223.43/api/mri/pathology/dzi-proxy/...` 형태가 아니면 → 프론트 프록시 경로 설정 확인.
- **open** 로그가 안 나오고 **15초 타임아웃**만 나오면 → Network 탭에서 `dzi-proxy` 요청 상태 확인.

---

## 2. 브라우저 Network 탭 (F12 → Network)

고해상도 뷰어를 연 상태에서:

1. **필터**: `dzi-proxy` 또는 `pathology` 로 걸어서 프록시 요청만 보기.
2. **실패한 요청(빨간색)** 이 있는지 확인.
3. 실패한 요청 클릭 → **Headers** 탭에서:
   - **Request URL**: `http://34.42.223.43/api/mri/pathology/dzi-proxy/https%3A%2F%2F...` 형태인지
   - **Status**: 403(허용 호스트 아님), 502(워커 연결 실패), 404(경로 없음) 등 확인
4. **Response** 탭에서 서버가 준 에러 메시지 확인.

- **403** → Django `PATHOLOGY_DZI_PROXY_ALLOWED_HOSTS`에 워커 ngrok 호스트(예: `ngrok-free.dev`) 포함 여부 확인.
- **502** → Django 서버에서 워커(ngrok)로 요청이 실패. 워커 PC/ngrok 상태 확인.
- **404** → 배포 서버에 `/api/mri/pathology/dzi-proxy/` 경로가 없음. URL 라우팅 확인.

---

## 3. Django 서버 로그

배포 서버에서 Django(또는 Gunicorn/uWSGI) 로그를 봅니다.

| 로그 | 의미 |
|------|------|
| `DZI 프록시 요청 (경로): target_host=xxx.ngrok-free.dev` | 브라우저가 프록시를 호출함 |
| `DZI 프록시 허용되지 않은 호스트: host=xxx.ngrok-free.dev, allowed=[...]` | **403 원인** — 허용 목록에 해당 호스트 추가 필요 |
| `DZI 프록시 업스트림 요청 실패: ...` | Django → 워커(ngrok) 요청 실패 → **502** |
| `DZI 프록시 성공: target_host=xxx.ngrok-free.dev` | 프록시 정상 응답 |

- **허용되지 않은 호스트**가 나오면 → `PATHOLOGY_DZI_PROXY_ALLOWED_HOSTS` 환경 변수에 워커 호스트(예: `ngrok-free.dev`) 추가.
- **업스트림 요청 실패**가 나오면 → 워커 PC 켜져 있는지, ngrok 주소가 맞는지 확인.

---

## 4. 체크리스트 요약

| 확인 위치 | 확인 내용 |
|-----------|-----------|
| **콘솔** | raw dziUrl 있는지, effectiveDziUrl이 프록시 URL인지, open / open-failed / 타임아웃 중 뭐가 나오는지 |
| **Network** | dzi-proxy 요청이 200인지, 403/502/404인지, 실패 시 Request URL·Response 내용 |
| **서버 로그** | DZI 프록시 요청/성공/허용되지 않은 호스트/업스트림 실패 로그 |

위 세 곳 로그를 캡처해 두면 원인 파악이 빠릅니다.
